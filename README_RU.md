# VPN Optimizer v2.5.1

Релиз v2.5.1. Версия испытана на маршрутизаторе с Entware, AWG Manager и sing-box: подтверждены запуск оптимизации через cron, выбор сервера, восстановление TPROXY и отправка Telegram-отчёта. Повтор отправки уведомления при временном сбое проверен отдельным имитационным тестом. Результаты статических и имитационных проверок приведены в `TEST_RESULTS.txt`. Совместимость с конкретным оборудованием и версиями компонентов необходимо проверять отдельно.

VPN Optimizer помогает выбирать и контролировать VPN-серверы на совместимом маршрутизаторе с Entware, AWG Manager и sing-box. Он использует существующую VPN-подписку и настроенный локальный HTTP-прокси. Установку VPN и правила общей маршрутизации программа не выполняет.

Низкая задержка ещё не означает хорошую скорость. Кроме того, короткий запрос может проходить даже тогда, когда передача пользовательского трафика работает плохо. Поэтому программа сочетает проверки HTTPS, загрузку данных и измерения скорости.

## Как выбирается сервер

Ночной цикл обновляет подписку, измеряет задержки, затем проверяет кандидатов через текущий прокси. Первоначально рассматриваются шесть серверов с малой задержкой; при необходимости добавляется текущий сервер. Проверяются HTTPS, загрузка 64 КиБ и скорость загрузки до 5 МиБ. Максимум — 18 измерений скорости и 30 попыток кандидатов.

Классы скорости: GOOD — от 20 Мбит/с, RESERVE — от 8 до 20, SLOW — ниже 8. Основной ночной выбор: минимальная задержка среди GOOD, а при их отсутствии — максимальная измеренная скорость. Финальная проверка и резервные переходы сохранены из v2.5. Серверы Trojan не участвуют в автоматическом выборе.

Во время ночного измерения и `/recheck` программа временно отключает клиентскую VPN-маршрутизацию через AWG Manager. Связь может прерваться, а трафик клиентов — пойти обычным маршрутом. После проверки восстанавливается прежний режим. При недоступном API восстановление может потребовать ручного вмешательства.

## Автоматическая работа

- Cron запускает проверку готовности каждые 10 минут. Оптимизация выполняется внутри выбранного часа один раз после успешного завершения; после ошибок возможны повторные попытки.
- Новый шаблон задаёт `NIGHT_HOUR=03` и `NIGHT_TZ=LOCAL`. Если оба ключа отсутствуют, действует прежнее время — 03 по Москве.
- Watchdog выполняет короткую HTTPS-проверку Discord, затем ждёт 60 секунд. Это приблизительно ежеминутная проверка, а не строгое расписание.
- Примерно раз в час для текущего сервера выполняется загрузка 5 МиБ. Два результата ниже 5 Мбит/с с интервалом 60 секунд запускают поиск замены со свежими измерениями кандидатов.
- При аварийном переключении сохраняются quick/deep-проверки. Периодический тест 64 КиБ не выполняется (остаются quick/deep-проверки при аварийном переключении).

## Telegram

Бот принимает команды только от перечисленных в конфигурации пользователей и только в личном чате.

| Команда | Действие |
|---|---|
| `/help` | Справка и настроенное ночное время |
| `/speed` | Три измерения до 5 МиБ текущего сервера, медиана и класс; без смены сервера |
| `/speedcache` | Сохранённые результаты последнего измерения |
| `/switch` | Выбор альтернативы из свежего speed-cache, HTTPS-проверка, попытка возврата при неудаче; без нового измерения скорости |
| `/recheck` | Проверка скорости кандидатов из существующего delay-cache; временное отключение клиентской VPN-маршрутизации |
| `/exclude`, `/excluded` | Исключение текущего сервера из подписки и просмотр исключений |
| `/restore N`, `/restoreall` | Возврат исключённых серверов и запуск существующего автовыбора |
| `/list`, `/check example.org`, `/del example.org` | Просмотр, проверка и удаление доменов выделенного rule-set |
| Домен или URL без команды | Добавление домена в выделенный rule-set |

Доменный rule-set должен принадлежать исключительно Optimizer. Неизвестные поля и чужие правила блокируют запись. Программа не создаёт этот набор и не подключает его к общей маршрутизации автоматически.

## Требования и ограничения

Нужны Entware под `/opt`, Linux `/proc`, root, Python 3 со стандартными модулями HTTPS, curl, BusyBox-совместимые shell-утилиты, cron и работающие API AWG Manager/Clash. API предполагаются локальными, HTTP, без отдельной авторизации; прокси — HTTP. Проверки используют Discord и Cloudflare. Telegram также работает через этот прокси.

Поддерживаемый формат ID/тегов ограничен латинскими буквами, цифрами, `_` и `-`, без начального дефиса. Не поддерживаются произвольные имена с пробелами и сложное форматирование списка selector. Preflight проверяет текущий ответ API; последующее изменение формата провайдером остаётся ограничением исходного алгоритма.

Ни список поддерживаемых моделей, ни минимальная память, ни универсальная совместимость версий AWG Manager/sing-box этим выпуском не подтверждены. Сначала должен работать сам VPN. Перед установкой проверьте требования и зависимости по [инструкции](INSTALL_RU.md). Особенности потери питания, сигналов остановки, повторной правки rule-set через другой интерфейс и ручного изменения системного времени описаны в [аудите безопасности](SECURITY_AUDIT_RU.md).

## Установка и дальнейшие обновления

См. [INSTALL_RU.md](INSTALL_RU.md): подготовка, первоначальная установка, проверка, изменение настроек, ручное обновление, откат и удаление. Для пошаговой установки с ИИ, включая настройку VPN с нуля, используйте [AI_INSTALL_PROMPT_RU.md](AI_INSTALL_PROMPT_RU.md).

Рабочая конфигурация — `/opt/etc/vpn-optimizer.conf`, root:root, `0600`. Постоянные данные — `/opt/var/lib/vpn-optimizer/`. При обновлении конфигурация и speed-cache сохраняются. Установщика, мигратора и менеджера обновлений нет. Процедура обновления начинается с этой версии; существующие исторические установки автоматически не переводятся.

## Проверки разработки

На Linux с Python 3 и BusyBox:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v
```

Тесты создают временные копии, заменяют curl и часы там, где это требуется, не обращаются к маршрутизатору. Отображение root-владельца в тестовых копиях позволяет выполнять их без root; проверка реального требования root отдельно тестируется подменой метаданных. Результаты и ограничения тестового окружения находятся в `TEST_RESULTS.txt`.
