# Установка и обновление VPN Optimizer v2.5.1

**Релизная инструкция v2.5.1.** Версия испытана на маршрутизаторе с Entware, AWG Manager и sing-box: подтверждены запуск оптимизации через cron, выбор сервера, восстановление TPROXY и отправка Telegram-отчёта. Совместимость с конкретными моделями и конфигурациями не гарантируется. Перед установкой проверьте совместимость компонентов и работоспособность существующего VPN; при установке с нуля следуйте части А.

## 1. Что такое VPN Optimizer и зачем он нужен?

### Почему удобно использовать VPN на роутере?

Обычно VPN устанавливают на телефон или компьютер. Но дома есть ещё телевизоры, приставки, планшеты и другие устройства, на которых отдельное приложение не всегда удобно, а иногда и невозможно.

Если настроить VPN на роутере, он сам будет направлять нужные подключения через VPN, а остальные — напрямую. Не придётся отдельно настраивать каждое устройство.

### В чём главная идея VPN Optimizer?

Хочется, чтобы VPN просто работал. Без постоянного поиска подходящего сервера и ручных переключений, когда что-то перестало открываться.

На практике VPN-сервер может отвечать на короткие проверочные запросы и выглядеть исправным, хотя сайты и приложения через него не работают. А бывает, что сервер доступен, но передаёт данные слишком медленно.

**VPN Optimizer проверяет не только отклик, но и реальную передачу данных.** В выбранное время он проверяет и сравнивает серверы, выбирает подходящий. В течение дня следит за текущим подключением и пытается найти замену при проблемах. Посмотреть результаты или запустить проверку можно через Telegram.

### А что делают AWG Manager и sing-box?

Это программы, которые обеспечивают VPN-подключение и маршрутизацию на роутере. AWG Manager уже умеет обновлять подписку и проверять доступность серверов, но короткий тест отклика не всегда показывает, насколько хорошо проходит обычный трафик.

**Optimizer дополняет существующие инструменты, а не заменяет их.** Сначала нужно настроить работающий VPN, а затем установить Optimizer для автоматического контроля качества.

### Если устанавливаете с помощью ИИ

Можно пройти всю настройку вместе с ChatGPT или другим ИИ-помощником. Для этого откройте [AI_INSTALL_PROMPT_RU.md](AI_INSTALL_PROMPT_RU.md), скопируйте задание в отдельный чат и приложите эту инструкцию и `README_RU.md`. Промпт включает как установку всех компонентов с нуля, так и установку на уже работающий VPN. **Никогда не прикладывайте в чат рабочий конфиг, токен Telegram и секретную ссылку подписки.**

## Часть А. Подготовка маршрутизатора

> Если Entware, AWG Manager, sing-box и VPN уже работают, не переустанавливайте их. Пройдите только проверки соответствующих пунктов и подготовьте отдельный rule-set.
>
> Здесь приведён порядок подготовки с нуля. Установочный пакет Entware зависит от архитектуры роутера, а названия пунктов веб-интерфейса — от версии ПО. Проверяйте их по ссылкам на документацию перед действиями, которые изменяют систему.

### 2. Роутер, накопитель, Entware и SSH

**Обязательно:** совместимое с AWG Manager устройство и прошивка, Entware в `/opt`, доступ root по SSH, Python 3, системные утилиты и место для компонентов. Для sing-box документация AWG Manager требует Entware на внешнем USB-накопителе. **Рекомендуется:** отдельный накопитель ext4 и резервная копия настроек роутера.

1. **Проверьте совместимость.** Узнайте модель, аппаратную ревизию, версию прошивки и архитектуру процессора. Сопоставьте их с [требованиями AWG Manager](https://hoaxisr.github.io/awg-manager-docs/install/). Не выбирайте установщик Entware по сходству названий моделей. Универсальный список устройств и минимальная RAM именно для Optimizer не подтверждены испытаниями.
2. **Подготовьте накопитель.** Подключите USB-накопитель с достаточным свободным местом. Для этой схемы рекомендуется ext4. **Форматирование удаляет все данные**: сначала сохраните нужные файлы. Убедитесь в веб-интерфейсе, что накопитель виден.
3. **Включите компоненты прошивки.** В меню управления системой найдите «Изменить набор компонентов». Для этой схемы в документации AWG Manager указаны OPKG, WireGuard, для TProxy — Netfilter, для ext4 — поддержка файловой системы. Названия и наличие пунктов зависят от прошивки. Примените изменения и убедитесь, что веб-интерфейс снова доступен.
4. **Установите Entware.** В веб-консоли (WebCLI) поддерживаемой платформы команда `opkg disk` позволяет выбрать накопитель, затем указать установочный URL **именно вашей архитектуры**. URL и полный синтаксис приведены в [официальной инструкции по установке Entware](https://hoaxisr.github.io/awg-manager-docs/install/). После установки проверьте сообщение об успешном завершении в системном журнале.
5. **Подключитесь по SSH.** Узнайте фактический порт SSH из настроек или журнала. На **компьютере** выполните:

```sh
ssh -p ПОРТ_SSH root@АДРЕС_РОУТЕРА
```

Задайте собственный пароль root (`passwd`, если это предусмотрено вашей сборкой Entware). Не открывайте SSH в интернет.

**В SSH роутера** проверьте:

```sh
id -u
ls -ld /opt /opt/bin /opt/etc/init.d /opt/var
/opt/bin/opkg --version
/opt/bin/opkg print-architecture
date
```

Ожидаются UID `0`, существующие каталоги `/opt`, сведения о пакетном менеджере и корректные дата/время. При ошибке сначала исправьте Entware или SSH.

6. **Подготовьте зависимости.** Через пакетный менеджер Entware установите только недостающие Python 3, curl, сертификаты HTTPS и `coreutils-nohup` (для запуска watchdog). Для ночного расписания необходим cron; на Entware с Vixie cron установите `opkg install cron`, если его нет. Затем **в SSH роутера** выполните:

```sh
/opt/bin/python3 -c 'import ssl, urllib.request, json, os; print("Python HTTPS modules: OK")'
curl --version
command -v awk sed grep sort tr cut head wc date mktemp tar cp chmod chown ps
mkdir -p /opt/lib /opt/var/run /opt/var/log /opt/var/lib
ls -ld /opt/bin /opt/etc/init.d /opt/lib /opt/var/run /opt/var/log /opt/var/lib
```

Ожидается `Python HTTPS modules: OK`, поддержка HTTPS у curl и наличие всех утилит. Команда `mkdir -p` только создаёт отсутствующие стандартные каталоги; существующие не заменяет. Если какой-либо каталог принадлежит не root или доступен для записи посторонним, не меняйте его права вслепую — сначала разберитесь с причиной. В случае ошибки установите недостающий пакет и повторите проверку. Системное время важно для сертификатов и ночного расписания.

### 3. AWG Manager, sing-box, подписка и маршрутизация

**Обязательно:** AWG Manager, sing-box, VPN-подписка с поддерживаемым selector, локальные HTTP API и HTTP-прокси, работающий TProxy. **Рекомендуется:** сперва проверить один домен и одно клиентское устройство, не направляя через VPN сразу всю сеть. **Не нужно:** устанавливать второй экземпляр sing-box, если им уже управляет AWG Manager.

#### 3.1. Установить AWG Manager

1. В [официальной инструкции AWG Manager](https://hoaxisr.github.io/awg-manager-docs/install/) выберите способ добавления его репозитория для своей архитектуры. Не запускайте непроверенные установочные скрипты из случайных источников.
2. После подключения официального репозитория **в SSH роутера** выполните:

```sh
/opt/bin/opkg update
/opt/bin/opkg install awg-manager
```

3. Установщик должен сообщить локальный URL веб-интерфейса. Откройте его **на компьютере в домашней сети**. Порт зависит от настроек: не полагайтесь на значение из чужой инструкции.
4. Включите авторизацию веб-интерфейса, если это поддерживается установленной версией. Не открывайте его в интернет. Проверьте доступность страницы настроек.

#### 3.2. Установить sing-box и добавить подписку

1. В AWG Manager откройте **Настройки → Уровень использования** и выберите уровень, открывающий разделы sing-box (в актуальной документации — **Расширенный** или выше).
2. Установите sing-box **средствами AWG Manager**. Проверьте версию и состояние в интерфейсе; второй независимый процесс не нужен. [Обзор sing-box](https://hoaxisr.github.io/awg-manager-docs/guide/singbox/).
3. Откройте **Главная → Sing-box подписки → Подписка по URL**. Введите собственный секретный URL **только в интерфейсе AWG Manager**, выберите название и **ручной выбор (selector)**. Автоматический `urltest` не подходит для управления выбранным сервером Optimizer.
4. Сохраните подписку, обновите список серверов, убедитесь, что он непустой, и выберите сервер вручную. Проверьте отображение активного сервера. [Руководство по подпискам](https://hoaxisr.github.io/awg-manager-docs/guide/singbox/subscriptions/).

Не передавайте URL подписки в чат с ИИ и не публикуйте его в отчёте диагностики.

#### 3.3. Настроить TProxy и проверить передачу трафика

1. В **Настройки → Уровень использования** включите уровень, на котором доступен Sing-box Router / TProxy (в актуальном интерфейсе — **Продвинутый**).
2. Перейдите в **Маршрутизация → Sing-box: TProxy**. В настройках движка проверьте Netfilter и TPROXY. Если интерфейс сообщает об отсутствующих компонентах, включите их через штатные настройки прошивки.
3. Для первого теста выберите **одно устройство** через соответствующую политику доступа. В простом режиме создайте правило «Что направить» → тестовый домен → «Куда» → своя VPN-подписка. Не меняйте сразу маршрут всей сети.
4. Примените конфигурацию, включите движок и проверьте его статус. В TProxy сохранённый, но не применённый черновик не влияет на трафик.
5. На тестовом устройстве откройте выбранный сайт и загрузите данные. В мониторинге соединений AWG Manager проверьте VPN-выход, а не `direct`. Проверьте также обычный сайт, не подпадающий под VPN-правило. **Одной успешной проверки задержки недостаточно.**

Скриншоты и шаги доступны в [официальном примере настройки TProxy](https://hoaxisr.github.io/awg-manager-docs/guide/singbox/router-quickstart/) и [справочнике Sing-box Router](https://hoaxisr.github.io/awg-manager-docs/guide/singbox/router/). Для другого интерфейса ориентируйтесь на фактические пункты меню.

#### 3.4. Записать параметры для Optimizer

| Параметр | Где взять |
|---|---|
| `SUB_ID` | ID нужной подписки AWG Manager, **не** её секретный URL |
| `SELECTOR` | Тег selector, относящийся к подписке |
| `AWGM_URL` | Локальный HTTP-адрес API AWG Manager |
| `CLASH_URL` | Локальный HTTP-адрес API Clash (sing-box) |
| `PROXY_URL` | Локальный HTTP-прокси sing-box для проверки передачи данных |

Посмотрите значения в интерфейсе и локальной конфигурации своей установки. Не используйте чужие порты без проверки. Требуется **HTTP-прокси**, а не только SOCKS5; его работоспособность, API и HTTPS проверит также `preflight.py`. Версия Optimizer не поддерживает отдельную авторизацию API, HTTPS API или пароль в URL. Не открывайте API и прокси в интернет.

ID и теги должны состоять из латинских букв, цифр, `_` и `-`, без начального дефиса. Не переименовывайте существующие теги вслепую. **К установке Optimizer переходите только после проверки реального VPN-трафика.**

### 4. Отдельный доменный rule-set

**Обязательно:** отдельный `inline` rule-set только для команд Telegram, подключённый к VPN-маршруту. Он не должен содержать чужих правил. Заполнить его десятками доменов заранее **необязательно**.

1. Откройте **Маршрутизация → Sing-box: TProxy**, переключитесь в **экспертный режим** отображения правил.
2. В секции **Rule-sets** выберите **«+ Набор»**. Тип — `Inline`, тег — например, `vpn-optimizer-domains`.
3. Добавьте только `domain_suffix` с тестовым `example.org` либо оставьте набор пустым, если интерфейс разрешает. Сохраните.
4. В секции **Правила маршрутизации** выберите **«+ Правило»** → условие: этот набор → действие: направить через свою VPN-подписку. **Примените** изменения.
5. Проверьте маршрут тестового домена и запишите тег для `RULESET_TAG`.

Допустимый вид объекта rule-set **в API** (пример структуры, не команда импорта):

```json
{"tag":"vpn-optimizer-domains","type":"inline","rules":[{"domain_suffix":["example.org"]}]}
```

Не используйте общий набор с IP-, портовыми и другими правилами. Если установленный API добавляет неизвестные поля, предварительная проверка может отказаться от установки; не удаляйте чужие правила ради совместимости. После установки этот набор должен редактировать только бот, без параллельной ручной правки.

### 5. Telegram-бот и свой ID

Создайте отдельного бота через [официальный BotFather](https://t.me/BotFather), командой `/newbot`, и сохраните токен локально. Порядок описан в [документации Telegram](https://core.telegram.org/bots/features#botfather). Не отправляйте токен другим людям, не вставляйте в URL браузера и не записывайте в команды оболочки.

Для работы нужен числовой User ID, а не `@username`. Получить его можно через [getUpdates собственного бота](https://core.telegram.org/bots/api#getupdates) до запуска Optimizer. Отправьте новому боту в личном чате точный текст `vpn-optimizer-setup`. Затем выполните **в SSH роутера** блок ниже. Он запросит токен и локальный прокси скрытым вводом, не сохранит их и покажет только найденный ID. Этот ID также не публикуйте.

```sh
/opt/bin/python3 - <<'PY'
import getpass, json, urllib.request
try:
    token = getpass.getpass('Токен нового бота: ')
    proxy = getpass.getpass('Локальный HTTP-прокси (http://host:port): ')
    opener = urllib.request.build_opener(urllib.request.ProxyHandler({'http': proxy, 'https': proxy}))
    with opener.open('https://api.telegram.org/bot' + token + '/getUpdates', timeout=15) as response:
        data = json.load(response)
    ids = {item['message']['from']['id'] for item in data.get('result', [])
           if item.get('message', {}).get('text') == 'vpn-optimizer-setup'
           and item['message'].get('chat', {}).get('type') == 'private'}
    if len(ids) != 1:
        print('Не найден единственный отправитель. Проверь новый бот и своё сообщение.')
    else:
        print('Твой User ID для локальной конфигурации:', next(iter(ids)))
except Exception:
    print('Не удалось получить ID. Проверь токен, прокси, HTTPS и отсутствие другого запущенного бота.')
PY
```

Не используйте один токен одновременно на нескольких экземплярах программы. Бот использует long polling; webhook и другой получатель обновлений должны отсутствовать. После запуска отправьте новое `/help`: сообщения, отправленные до старта, могут быть отброшены.

## Часть Б. Установка Optimizer

### 6. Перенос файлов

На **компьютере** после получения согласованного архива:

```sh
scp -P ПОРТ_SSH vpn-optimizer-v2.5.1.tar.gz root@АДРЕС_РОУТЕРА:/tmp/
```

В **SSH роутера**:

```sh
umask 077
export PATH=/opt/bin:/opt/sbin:/usr/sbin:/usr/bin:/sbin:/bin
cd /tmp
tar -xzf vpn-optimizer-v2.5.1.tar.gz
SOURCE=/tmp/vpn-optimizer-v2.5.1
ls "$SOURCE/bin" "$SOURCE/lib/vpn-optimizer" "$SOURCE/tools"
```

Распаковка идёт отдельно от рабочей установки. Папку `$SOURCE` не используй для хранения токенов или резервных копий. В релизный комплект входит `SHA256SUMS` для проверки целостности поставляемых файлов.

Перед копированием файлов проверьте внутренний список (все строки должны иметь результат OK):

```sh
(cd "$SOURCE" && sha256sum -c SHA256SUMS)
```

При ошибке остановитесь и получите комплект заново. Для архива рядом с ним публикуется отдельный `SHA256SUMS`: в каталоге загрузки выполните `sha256sum -c SHA256SUMS` до распаковки (на macOS — `shasum -a 256 -c SHA256SUMS`). Контрольная сумма проверяет целостность, но сама по себе не удостоверяет автора.

### 7. Конфигурация

Создать файл только если его ещё нет:

```sh
if [ -e /opt/etc/vpn-optimizer.conf ] || [ -L /opt/etc/vpn-optimizer.conf ]; then
    echo 'Конфигурация уже существует; не заменена'
else
    (umask 077; set -C; cat "$SOURCE/etc/vpn-optimizer.conf.example" > /opt/etc/vpn-optimizer.conf)
fi
```

Открой файл локальным редактором, например `vi /opt/etc/vpn-optimizer.conf`. Заполни все заглушки своими значениями. Если редактор незнаком: в `vi` клавиша `i` включает ввод, `Esc`, затем `:wq` и Enter сохраняют файл. Секреты находятся только здесь, не в скриптах.

```sh
chown 0:0 /opt/etc/vpn-optimizer.conf
chmod 600 /opt/etc/vpn-optimizer.conf
/opt/bin/python3 "$SOURCE/lib/vpn-optimizer/common.py"
```

Ожидается `OK: config is valid; values not displayed`. Файл должен быть обычным, без символической ссылки. Формат — по одному `KEY=VALUE` на строку, без кавычек, команд и комментария после значения. `TG_ALLOWED_IDS` — положительные ID через запятую без пробелов. Проверка токена подтверждает формат, а не его действительность.

### 8. Ночное время

Новый шаблон: `NIGHT_HOUR=03`, `NIGHT_TZ=LOCAL`. Час — ровно две цифры от `00` до `23`.

| `NIGHT_TZ` | Значение |
|---|---|
| `LOCAL` | Системное время роутера |
| `MSK-3` | Москва, постоянный UTC+03:00 |
| `UTC0` | UTC |
| `UTC-3` | UTC+03:00 |
| `UTC+5:30` | UTC−05:30 |

У фиксированных POSIX-поясов знак обратный привычному UTC-смещению. Поддержаны часы 0–14 и необязательные минуты `:00`–`:59`. Региональные имена вроде `Europe/Moscow` и сложные правила перехода на летнее время не поддерживаются. Для `LOCAL` действует системная настройка.

Если оба новых параметра отсутствуют, сохраняется 03 по Москве. Если отсутствует один — для него используется `03` либо `LOCAL`. Пустое или неверное значение вызывает ошибку.

Cron проверяет готовность в 00, 10, 20, 30, 40 и 50 минут каждого часа. После успешного цикла повтор в той же дате блокируется. В существующем `nightly-last-date` сохраняются дата, время успеха и пояс; при смене `NIGHT_TZ` дополнительно блокируется запуск раньше чем через 24 часа после успеха. Из-за этого следующий цикл после смены пояса может быть пропущен. Обычные повторные попытки после ошибок остаются прежними.

Ограничение: изменение системного пояса при сохранённом `LOCAL`, ручной скачок часов или старая отметка только с датой не дают полной защиты от повторного цикла. Меняй такие настройки при временно снятом cron-задании и возвращай его после следующей ночи. Не удаляй отметку успеха ради немедленного запуска. Ручной `--force` сознательно обходит расписание.

### 9. Проверка перед установкой

```sh
/opt/bin/python3 "$SOURCE/tools/preflight.py"
```

Проверка читает конфигурацию и локальные API, выполняет один короткий HTTPS-запрос Discord через уже выбранный прокси, проверяет cron и необходимые компоненты. Серверы, rule-set, подписка и маршрутизация не изменяются. Измерение скорости не запускается.

Проверь, что будущие пути `/opt/bin/vpn-*.sh`, `/opt/lib/vpn-optimizer`, `/opt/etc/telegram-vpn-bot`, оба сервиса `S99vpn-watchdog` и `S99telegram-vpn-bot` не заняты другими программами. Если заняты — остановись; имя файла само по себе не доказывает принадлежность Optimizer. Для существующей установки этой версии используй раздел обновления.

### 10. Резервная копия

Выполни также перед обновлением. Каталог резервной копии содержит секреты; не добавляй его в публичный архив. Для обновления сначала выполни остановку из раздела 15, сохранив сведения о ранее работавших сервисах.

```sh
umask 077
mkdir -p /opt/var/backups
BACKUP_DIR=$(mktemp -d /opt/var/backups/vpn-optimizer.XXXXXX) || exit 1
: > "$BACKUP_DIR/files.list"
for ITEM in opt/bin/vpn-optimize.sh opt/bin/vpn-delay-scan.sh opt/bin/vpn-watchdog.sh opt/bin/vpn-watchdog-loop.sh opt/lib/vpn-optimizer opt/etc/telegram-vpn-bot opt/etc/init.d/S99vpn-watchdog opt/etc/init.d/S99telegram-vpn-bot opt/etc/vpn-optimizer.conf opt/var/lib/vpn-optimizer; do
    if [ -e "/$ITEM" ]; then printf '%s\n' "$ITEM" >> "$BACKUP_DIR/files.list"; fi
done
if [ -s "$BACKUP_DIR/files.list" ]; then
    (
        cd / || exit 1
        set --
        while IFS= read -r ITEM; do
            set -- "$@" "$ITEM"
        done < "$BACKUP_DIR/files.list"
        tar -czf "$BACKUP_DIR/files.tar.gz" "$@"
    ) || { echo 'Не удалось создать резервную копию. Остановите установку.'; false; }
fi
if [ -f /opt/var/spool/cron/crontabs/root ]; then
    cp -p /opt/var/spool/cron/crontabs/root "$BACKUP_DIR/crontab.root"
fi
printf 'Резервная копия: %s\n' "$BACKUP_DIR"
ls -l "$BACKUP_DIR"
```

Если какая-либо команда завершилась с ошибкой, не копируй новые файлы. Для архивации используется список аргументов, совместимый в том числе с BusyBox `tar` (его реализация может не поддерживать ключ `-T`). При наличии архива проверь его чтение:

```sh
if [ -f "$BACKUP_DIR/files.tar.gz" ]; then tar -tzf "$BACKUP_DIR/files.tar.gz" >/dev/null; fi
```

Запиши путь `$BACKUP_DIR` отдельно: переменные теряются при переподключении SSH. Сведения о cron до его временного удаления при обновлении сохраняются отдельно в разделе 15.

### 12. Cron: добавить только своё задание

Скрипт `vpn-optimize.sh` самостоятельно задаёт `PATH` с `/opt/bin`: у Vixie cron он может отличаться от интерактивной SSH-сессии, а на некоторых роутерах `/bin/date` отсутствует. Если используется ранее скачанная сборка без этой строки, обнови скрипт перед ночной эксплуатацией.

Используется штатный cron Entware. Убедись, что он читает `/opt/var/spool/cron/crontabs`: проверь настройки установленного сервиса и аргументы процесса `cron` (Vixie) или `crond` (BusyBox). Наличие процесса само по себе этого не доказывает. Если используется другой каталог/пользовательский crontab, приведённые команды не подходят.

Существующий сервис cron не заменять. Если он ещё не запущен, используй штатную команду запуска своего пакета после проверки его настроек. Не останавливай общий cron ради Optimizer.

```sh
CRONFILE=/opt/var/spool/cron/crontabs/root
CRON_JOB='*/10 * * * * /opt/bin/vpn-optimize.sh # vpn-optimizer'
mkdir -p /opt/var/spool/cron/crontabs
touch "$CRONFILE"
chmod 600 "$CRONFILE"
if grep -Fq '/opt/bin/vpn-optimize.sh' "$CRONFILE"; then
    echo 'Запись optimizer уже существует; проверь её, новая не добавлена'
else
    printf '\n%s\n' "$CRON_JOB" >> "$CRONFILE"
fi
```

Проверь только запись Optimizer, не публикуя чужие задания:

```sh
grep -F '/opt/bin/vpn-optimize.sh' "$CRONFILE"
```

Для установленного Vixie cron Entware (пакет `cron`) выполни:

```sh
/opt/bin/crontab "$CRONFILE"
/opt/bin/crontab -l | grep -F '/opt/bin/vpn-optimize.sh'
```

Ожидается ровно одна активная строка с расписанием `*/10 * * * *`. **Для Vixie cron после изменения файла обязательно зарегистрируй его командой** `/opt/bin/crontab "$CRONFILE"`, затем проверь `/opt/bin/crontab -l`. Простое редактирование файла не гарантирует, что Vixie cron применит изменение. Для BusyBox crond используй его штатный способ перечитывания. После следующего ночного окна проверь фактическое выполнение. Не использовать `killall crond`.

### 13. Запуск и проверка

```sh
/opt/etc/init.d/S99vpn-watchdog start
/opt/etc/init.d/S99telegram-vpn-bot start
/opt/etc/init.d/S99vpn-watchdog check
/opt/etc/init.d/S99telegram-vpn-bot check
```

Оба `check` должны сообщить, что сервис работает. Init-файлы лежат в стандартном каталоге Entware; фактический автозапуск зависит от интеграции Entware с загрузкой роутера и проверяется отдельно после разрешённой перезагрузки.

Отправь боту новое `/help`, затем `/list`. Проверь отображённое расписание. `/speedcache` до первого ночного цикла может сообщить, что данных нет. `/switch` требует свежего speed-cache, а `/recheck` — существующего delay-cache.

Для первого полного цикла можно дождаться ночи либо осознанно выполнить вручную:

```sh
/opt/bin/vpn-optimize.sh --force
```

Эта команда обновляет подписку, переключает серверы, расходует трафик и временно отключает VPN-маршрутизацию клиентов. Запускай её в удобное время и дождись завершения. Не закрывай сессию во время проверки. После неё проверь `/speedcache`, реальный доступ с клиентских устройств и режим маршрутизации в AWG Manager. Затем можно проверить `/speed` и `/switch`.

В течение следующего часа проверь измерение скорости, а после ночного окна — ночной отчёт и отсутствие повторных успешных циклов. Не имитируй аварии на рабочей сети без отдельного плана.

### 14. Изменение настроек

Сначала сними задание cron и останови сервисы по разделу 15. Сохрани резервную копию, отредактируй только `/opt/etc/vpn-optimizer.conf`, верни `root:root` и `0600`, выполни проверку конфигурации и preflight. Затем запусти сервисы и верни cron-запись по разделам 12–13. Бот читает конфигурацию при старте; одного изменения файла для него недостаточно.

### 15. Как обновить VPN Optimizer

Этот порядок предназначен для последующих обновлений начиная с v2.5.1. Формат speed-cache сохраняется; новые параметры добавляются вручную, если это требуется в примечаниях новой версии. Автоматического мигратора нет.

Сначала скачай и распакуй новую версию отдельно, как в разделе 6, и установи `SOURCE` в её каталог. Прочитай особенности обновления. Затем в SSH:

1. Посмотри `check` обоих сервисов и запиши, какие работали. Временно не отправляй команды боту.
2. Сохрани исходный crontab и точечно сними только собственную маркированную строку:

```sh
umask 077
CRONFILE=/opt/var/spool/cron/crontabs/root
CRON_JOB='*/10 * * * * /opt/bin/vpn-optimize.sh # vpn-optimizer'
mkdir -p /opt/var/backups || exit 1
CRON_SAVED=$(mktemp /opt/var/backups/vpn-optimizer-cron.XXXXXX) || exit 1
cp -p "$CRONFILE" "$CRON_SAVED" || exit 1
CRON_TMP=$(mktemp /opt/var/spool/cron/crontabs/.vpn-optimizer.XXXXXX) || exit 1
awk -v job="$CRON_JOB" '$0 != job {print}' "$CRONFILE" > "$CRON_TMP" && chmod 600 "$CRON_TMP" && mv "$CRON_TMP" "$CRONFILE" || exit 1
```

Запиши путь `$CRON_SAVED`; он содержит личные задания. Если строка была изменена вручную или существуют другие запуски Optimizer, убери именно их вручную. Проверь отсутствие активных записей для `/opt/bin/vpn-optimize.sh`. Не меняй чужие задания.

3. Останови сервисы:

```sh
/opt/etc/init.d/S99telegram-vpn-bot stop
/opt/etc/init.d/S99vpn-watchdog stop
ps | grep -E '[v]pn-(optimize|watchdog|delay-scan)|[t]elegram-vpn-bot'
ls -d /tmp/vpn-optimize.lock /tmp/vpn-watchdog.lock /tmp/vpn-delay-scan.lock 2>/dev/null
```

`stop` завершает основной процесс, но дочерняя операция могла ещё работать. Дождись отсутствия процессов проверки и блокировок. Не удаляй блокировки и не заменяй файлы, пока операция выполняется. При оставшейся блокировке без процесса сначала проверь журналы и состояние AWG Manager; не запускай параллельный экземпляр.

4. Выполни резервное копирование из раздела 10. Сохрани `$CRON_SAVED` рядом с `$BACKUP_DIR` как исходный crontab:

```sh
cp -p "$CRON_SAVED" "$BACKUP_DIR/crontab.before-update"
```

5. Проверь конфигурацию и preflight кодом новой версии. Не заменяй конфиг шаблоном. Если появились обязательные параметры, добавь их вручную по примечаниям версии.
6. Скопируй файлы и выполни синтаксические проверки из раздела 11. Каталоги постоянных данных и содержимое speed-cache не удаляются.
7. Верни одну cron-запись по разделу 12 и запусти ранее работавшие сервисы по разделу 13. Проверь Telegram, watchdog и сохранённый speed-cache. В удобное время проверь основные команды.

При повторении этой процедуры конфигурация сохраняется, а cron-запись не дублируется. Не выполняй копирование, если ещё не выяснено, каким экземпляром программы заняты файлы.

### 16. Ручной откат

Сними задание cron, останови сервисы и дождись завершения операций, как в разделе 15. Укажи точный ранее записанный каталог резервной копии:

```sh
BACKUP_DIR=/opt/var/backups/ИМЯ_СВОЕЙ_КОПИИ
ls -l "$BACKUP_DIR"
tar -tzf "$BACKUP_DIR/files.tar.gz"
```

Проверь, что это твоя закрытая копия нужной установки, а не релизный архив. Затем восстанови сохранённые файлы:

```sh
tar -xzf "$BACKUP_DIR/files.tar.gz" -C / || exit 1
```

Архив возвращает сохранённое состояние постоянных данных на момент копии. Если новая версия добавляла файлы, отсутствующие в старой, удаляются только такие файлы из её опубликованного перечня изменений; общие каталоги вслепую не очищаются.

Не подменяй весь текущий crontab резервной копией: со времени копирования могли появиться чужие задания. По сохранённой копии верни только прежнюю запись Optimizer, если она была. Запусти только ранее работавшие сервисы и повтори проверки. При откате неработающей маршрутизации сначала проверь и восстанови нужный режим в интерфейсе AWG Manager.

### 18. Если что-то не работает

| Симптом | Проверка |
|---|---|
| Ошибка конфигурации | root-владелец, `0600`, обычный файл, все заглушки заполнены, допустимые форматы |
| Preflight: компоненты | Команды раздела 2, PATH, модули Python, работающий sing-box |
| Preflight: API/selector | Свои адреса/порты, API без авторизации, ID подписки и соответствующий selector, формат тегов |
| Preflight: rule-set | Отдельный inline-набор с `tag/type/rules` и только `domain_suffix` внутри правил; дополнительные служебные поля верхнего уровня API допустимы, дубликаты тега запрещены |
| Preflight: HTTPS | Выбранный сервер, HTTP-прокси, DNS, дата и сертификаты; сообщение не доказывает неисправность самого Optimizer |
| Бот молчит | Токен, положительный User ID, личный чат, новое сообщение после запуска, доступ Telegram через прокси, отсутствие второго получателя |
| Ночной цикл не запускается | Cron-каталог, одна запись, время/пояс, отметка успешного цикла, активные блокировки |
| `/switch` или `/recheck` недоступен | Свежий speed-cache или существующий delay-cache соответственно; первый полный цикл ещё не выполнен |
| После проверки нарушена маршрутизация | Проверить режим AWG Manager и выбранный сервер; при недоступном API требуется ручное восстановление |

Локальные журналы: `/opt/var/log/vpn-watchdog.log`, `/opt/var/log/vpn-watchdog-loop.log`, `/opt/var/log/telegram-vpn-bot.log`. Они могут содержать имена серверов и сведения о работе сети. Не публикуй их целиком и никогда не прикладывай рабочий конфиг или резервную копию. Полные тела ошибочных ответов API и Telegram ID программа больше не печатает.
