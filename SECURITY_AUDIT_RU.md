# Аудит безопасности VPN Optimizer v2.5.1

Исходный аудит: 01.11.2026; предыдущая проверка выпуска: 02.11.2026; проверка чистого комплекта: 07.11.2026.

Ранний аудит выполнялся с имитациями API. Позднее, 04–07.11.2026, по сохранённому отчёту проекта на реальном Hopper 4G+ (NC-2312, EA) подтверждены полный цикл через Entware cron, выбор сервера, восстановление TPROXY и отправка Telegram-отчёта. Снимок версий ПО от 01.11.2026 приведён в INSTALL_RU.md и INSTALL_EN.md; он не означает повторную проверку этих версий на дату выпуска. При подготовке чистого комплекта рабочие маршрутизаторы не использовались и не изменялись.

## Что проверено

Проверены 23 файла текущего main, включая SHA256SUMS. История Git не переносится. Проверка охватывает состав, секреты и персональные сведения, синтаксис, документацию и контрольные суммы. При получении исходников обнаружены шесть устаревших записей SHA256SUMS; для окончательного комплекта список пересчитан полностью.

По поиску типовых признаков и просмотру конфигурации, адресов и тестовых данных реальных токенов, личных пользовательских ID, приватных ключей, секретных URL подписки, личных адресов, имён маршрутизаторов, журналов и резервных копий не обнаружено. Это проверка содержимого выпуска, а не гарантия обнаружения любого возможного секрета. В шаблоне используются заглушки, в тестах — синтетические данные; loopback и документальные примеры адресов сохранены.

## Исправления

| Проблема v2.5 | Исправление v2.5.1 |
|---|---|
| Shell исполнял содержимое конфигурации | Небольшой `common.py` читает только данные. Shell получает разрешённые несекретные поля через `read`, без source/eval |
| Python проверял только отсутствие прав группы/остальных | Открытый файл проверяется через fstat: обычный файл, UID 0, ровно 0600; финальная символическая ссылка запрещена |
| Форматы параметров не проверялись согласованно | Общая проверка обязательных ключей, заглушек, повторов, неизвестных ключей, ID/тегов, HTTP URL без паролей и путей, Telegram-параметров и времени |
| Предсказуемые рабочие файлы в общем `/tmp` | `mktemp -d`, `umask 077`, проверка создания, освобождение своей блокировки при отказе |
| Бот мог потерять чужие правила при пересоздании набора | Отдельный inline rule-set; служебные поля объекта допускаются, внутри правил разрешён только domain_suffix; проверка при preflight и перед каждой записью |
| Между чтением для команды и записью данные могли измениться | Повторное чтение и сравнение списка; при обнаруженном изменении — отказ |
| Ошибки могли содержать тело API, URL или Telegram ID | Тела ответов и личные ID убраны из диагностики; внешние исключения показываются без их текста |
| В комплекте находились общий cron-сервис и root-crontab | Эти файлы исключены; инструкция добавляет/удаляет только собственную запись |
| Инструкция была частной процедурой миграции | Отдельные ручные процедуры новой установки, обновления начиная с v2.5.1, резервного копирования, отката и удаления |

Общий модуль — обычные функции с фиксированной схемой, не конфигурационный фреймворк. Новые библиотеки и сервисы не добавлялись. Исторический мигратор исключён из публичного комплекта.

Время задаётся `NIGHT_HOUR` и `NIGHT_TZ`. Отсутствие обоих сохраняет 03 по Москве. В существующей строке `nightly-last-date` добавлены время успеха и выбранный пояс; отдельного файла или планировщика нет. После смены пояса повтор раньше 24 часов блокируется, обычный интервал повторных попыток остаётся 600 секунд. Подробности и ограничения — в INSTALL_RU.md.

## Границы гарантии

- Нужна доверенная root-среда Entware. Проверка конфигурации не защищает от администратора root, изменения системного Python или подмены самих исполняемых файлов. Каталоги программы и состояния должны принадлежать root и не допускать запись другими пользователями.
- Локальные API рассчитаны на доверенное окружение без отдельной авторизации. Не открывать их наружу. Произвольные API-схемы и имена тегов не поддерживаются.
- Preflight проверяет текущие данные. После обновления подписки провайдер может изменить формат тегов/ответов. Полная переработка shell-разбора отложена.
- Между последним GET и POST rule-set остаётся небольшое окно внешней правки. Условная запись API не подтверждена. Выделенный набор должен редактироваться только Optimizer; гарантии атомарности между несколькими редакторами нет.
- Ночной цикл и recheck временно отключают клиентскую VPN-маршрутизацию. Это прежнее поведение. При недоступном AWG Manager восстановление может не состояться; нужен ручной контроль.
- Потеря питания, SIGKILL, некоторые сценарии SIGTERM и остановка дочерних процессов не стали транзакционными. Перед обновлением требуется дождаться завершения операций и проверить блокировки; удалять активные блокировки нельзя.
- При ручном переводе системных часов, смене системного пояса внутри LOCAL или старой отметке только с датой полная защита от повторного запуска не гарантируется. Смена явного пояса может отложить следующий цикл. Ручные force/recheck не подчиняются ночному расписанию.
- Журналы всё ещё содержат эксплуатационные сведения и имена серверов. Их нельзя считать общедоступными. Резервные копии содержат конфигурацию и должны оставаться закрытыми.
- Ручное обновление допускает простой. При ошибке копирования не запускать частично обновлённый комплект: повторить копирование после устранения причины либо выполнить ручной откат.

## Что проверяется автоматически

Существующие тесты v2.5 сохранены, кроме теста исключённого мигратора. Добавлены проверки командной инъекции, строгих прав/владельца, ссылок и специальных файлов, параметров времени, повторов, rule-set, отсутствия утечек в обработчиках ошибок, отказа mktemp, preflight и команд установки/обновления.

Команды копирования, создания конфигурации, резервного копирования, восстановления и изменения cron выполняются на временном дереве с подменённым корнем. Проверяется сохранность пользовательского конфига, speed-cache и посторонних cron-строк. Init-скрипты испытываются с безвредными процессами-заглушками.

Linux-прогон выполняется в контейнере Python/Alpine с BusyBox, отключённой сетью, исходниками только для чтения и временной файловой системой. Curl, серверы и часы подменяются по сценарию. Это не испытание реального VPN. Фактические числа и результаты находятся в TEST_RESULTS.txt.

Дополнительно исходная v2.5 и новая версия сравниваются на одинаковых сценариях: порядок переключений/измерений/изменений маршрутизации, итоговый сервер, код возврата, протокол shell-команд и содержимое speed-cache/дневного состояния. Изменённое отображение времени и служебная отметка расписания оцениваются отдельно.

## Проверки при новой установке и оставшиеся ограничения

Этот перечень предназначен для новой установки; он не отменяет уже подтверждённые практические результаты выше. Автозапуск после перезагрузки, аварии и все сочетания окружения не считаются проверенными автоматически.

1. Версии и формат локальных API, реальные ID/теги, структуру выделенного rule-set и связь его с маршрутом.
2. Доступность сертификатов, Python-модулей, curl, mktemp и системного date; корректность LOCAL и выбранного фиксированного пояса.
3. Запуск, остановку, повторный старт и автозапуск двух сервисов; завершение дочерних операций при обслуживании.
4. Чтение cron нужного каталога, отсутствие дублирования и фактический ночной запуск.
5. Telegram, доступ только разрешённым пользователям и безопасное добавление/удаление тестового домена.
6. Quick-проверки, ежечасную загрузку 5 МиБ, ночной цикл, speed-cache, switch/recheck и восстановление режима маршрутизации.
7. Ручное обновление и откат с сохранением индивидуального конфига, данных и чужих cron-заданий.
8. Потребление RAM, места и CPU на конкретной модели. Совместимость непроверенных устройств не заявляется.

## Backlog: обнаружено, но не исправлялось в этом выпуске

- `load_offset()` бота вызывает отсутствующую `read_text()` и возвращает None через обработчик исключения. Сохранённый offset при старте не читается; требуется отдельное исправление и тестирование обработки обновлений Telegram.
- Уведомление о низкой скорости не объясняет последующий поиск замены watchdog.
- Shell-разбор JSON и ограничение тегов; возможное изменение формата ответов после обновления подписки.
- Различия принятия результата speed-test в ночном optimizer и watchdog.
- Более строгая проверка возврата сервера в отдельных аварийных ветках, обработка сигналов и завершение групп процессов.
- HTTP 500 при refresh, расширенные тайм-ауты, диагностика TProxy/DNS, ротация журналов и новые Telegram-функции.

Перечисленное не исправлялось автоматически, чтобы не менять согласованные алгоритмы v2.5.
